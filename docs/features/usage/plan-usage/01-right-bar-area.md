Decisions: **the area** (design.md § The right bar): `rightBar` sits beside `main` on its right in every mode. It holds contributions with no alignment tracks, like `sideBar`. It hides while it holds no contribution through the existing `applyHidden` default branch (the status bar's rule). Its resize handle hides with it
           **the grid** in `shell.css`: a fourth column named `right`, after main, spanning the main and panel rows as the side bar's column does: rows `'title title title title'`, `'activity side main right'`, `'activity side panel right'`, `'status status status status'`; columns `auto auto minmax(0, 1fr) auto`. The side bar's `over` rule (`grid-column: 3; grid-row: 2 / 4`) stays as it is. `.shell-right-bar` takes `grid-area: right`, `width: calc(var(--shell-right-bar-width) * 1px)`, `min-height: 0`, `overflow-y: auto`, `padding: var(--wg-space-1)` and a 1px `--wg-material-chrome-edge` hairline on its left edge (the edge toward the content)
           **the handle**: `div.shell-right-bar-handle`, a child of `root` like `shell-side-bar-handle`, appended again in `fillElements` so it survives a layout swap. It lies centred on the right bar's start edge (`grid-area: right; justify-self: start`) with the side handle's negative margins, width, `::after` line and hover and `is-active` colours. Write the shared declarations once in a rule over both handle classes; each class keeps only its `grid-area` and `justify-self`
           **the divider**: a second `createSplitDivider` instance in `mountShell`, not a generalised bar object. Its options: `stateKey: 'right-bar-width'`, `sizedPane: 'end'`, limits `{ initial: <open width>, min: RIGHT_BAR_MIN, endMin: MAIN_MIN }` with `RIGHT_BAR_MIN = 200`, `measure()` returning `{ left: main.left, span: rightBar.right - main.left }` from the two elements' `getBoundingClientRect()`, the same `promptAnchor.anchor` and `timers`. Its stored-width fallback is the side bar's `sideBarState` pattern: lift it into one private static helper `openWidthState(uiState: UiState, openWidth: () => number): UiState` used by both dividers
           **the open width**: the `rightbar-width` token as `root` computes it (`--wg-rightbar-width`), by the side bar's rule: a pixel length is taken, any other value takes `RIGHT_BAR_FALLBACK_WIDTH = 300`. Generalise `sideBarOpenWidth(root)` into one private static `openWidthToken(root: HTMLElement, property: string, fallback: number): number` used by both bars
           **`reloadBarOpenWidths`** replaces `reloadSideBarOpenWidth`: it reads both tokens again and calls `reloadWidth()` on both dividers. `renderer.ts`'s theme applier calls it in place of the old name, and its comment names both tokens
           **the split core's `sizedPane`** (default `'start'`, so every existing caller is unchanged): the pane whose width the divider holds. With `'end'`, `measure` still returns the start pane's left edge and the span both panes share; the width is measured from the span's right edge (`left + span`) leftward. A press keeps `grabOffset = (left + span - clientX) - clampSplitWidth(width, options, span)`; a move shows `clampSplitWidth(left + span - clientX - grabOffset, options, span)`; a nudge `left` widens and `right` narrows (the direction is flipped before `nudgedSplitWidth`). `min` and `initial` describe the sized pane and `endMin` the other pane's least width. Rewrite the `SplitLimits` comment in `split-width.ts` to say that `min` is the sized pane's least width and `endMin` the least width it leaves the pane beside it. `SplitLimits.endMin` is not renamed: it has 14 non-test uses across five plugins
           **drawing a narrow window**: the right bar has no `over` or `hidden` layout. It stays beside at every window width. Shown, it draws `clampSplitWidth(width, limits, span)`: main keeps `MAIN_MIN` while the span allows; when the span is less than `RIGHT_BAR_MIN + MAIN_MIN`, `RIGHT_BAR_MIN` wins. Hidden, it draws its width unclamped (the side bar's `hidden` precedent). The drawn width only is clamped; `uiState` keeps the user's width. The width is `--shell-right-bar-width` on `root`, unitless pixels
           **the two bars together**: one private `drawBarWidths()` draws the side bar, then the right bar. It runs on the root's `ResizeObserver`, in `layOutSideBar`, and each time the right bar's hidden state changes (its first contribution, its last dispose). The side bar draws first, so it gives way first in a window too narrow for both. Each divider's own `show` draws only its own bar: its clamp already leaves main its least width
           **chrome layouts**: `rightBar` joins `CHROME_AREAS`, so a user shell layout's CSS restyles its frame as it does the side bar's. `layout.d.ts`'s comment lists the right bar among those elements
           **page API**: `pluginAreas` adds `rightBar: areas.rightBar`. The comments above `PageApiDeps` and `createPageApi` and above `PluginAreas` name the right bar among the plugin areas
           **keyboard resize**: the right bar's handle carries the divider core's `⌥⇧H ◂ ▸ ⌥⇧L` prompt, as every divider does. `createPaneResize(shell.sideBarDivider)` in `renderer.ts` is unchanged: the resize keys move the side bar unless a view sets a target. No view targets `Shell.rightBarDivider` in this plan
           **gallery test layout**: `testShellLayout` adds `rightBar: element('div', 'gallery-test-right-bar material-chrome material-chrome--dense')`. `gallery.css` puts it between main and the activity bar: rows `'title title title title'`, `'status status status status'`, `'side main right activity'`, `'side panel right activity'`; columns `auto minmax(0, 1fr) auto auto`. `.gallery-test-right-bar` takes `grid-area: right`, the `--shell-right-bar-width` width, `min-height: 0`, `overflow-y: auto` and a `--wg-border-default` left border. The area named `right` places the shell's right bar handle in this layout too. The side bar's `over` rule (`grid-column: 2`) stays. The comment above `.gallery-test-shell` names the right bar

           **comments**: the doc comments of `Shell`, `mountShell`, `AREA_CLASSES` and the `.shell` grid comment in `shell.css` describe the right bar, its handle, its stored width and its narrow-window rule
