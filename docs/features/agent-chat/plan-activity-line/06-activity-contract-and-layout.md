Decisions: **contract** (`layout.d.ts`): `ActivityInput` comments say: `steps` in entry order, each the step's entry input; `current` is the last step; `live` holds while the session works on this run and it is the last entry; `open` holds while the user has the line open, and then the part draws only its header and the app places the step rows under it; `startedAt` is when the run began (the entry before it, epoch ms); `endedAt` when it ended, null while live; `now` is the time of this draw or update, which the app sends again once a second while the run is live, so a live line's time is `now - startedAt` and a finished one's `endedAt - startedAt`. `collapsibleRow` is commented as "a plain one-line row, no card, that opens `body()` in place under it; Enter on the focused entry toggles it with the entry's expanders", next to `collapsibleCard`. The `ChatLayout.activity` comment: "One run of the agent's steps (tool, thinking, raw entries between two other entries), drawn into its slot; the app keeps the cursor, the click that opens it and the step rows." `CompleteChatLayout` gets `activity` through `Required<ChatLayout>` with no edit
           **kit** (`chat-kit.ts`): `collapsibleRow(parent, options)` calls `createCollapsibleCard({ ...options, plain: true })`, pushes the handle into the kit's expanders list (as `collapsibleCard` does) and appends its element to `parent`
           **built-in steps** (`layout.js`): `tool` draws `collapsibleRow` with the status dot leading, `summary: toolLine(input)`, `mono: true`, the same body and update as today. `thinking` and `raw` draw `collapsibleRow` with summaries `Thinking` and `Raw event` and the same bodies as today. Root classes stay `chat-entry chat-tool` / `chat-thinking` / `chat-raw`. `user`, `assistant`, `permission`, `result`, `notice` do not change
           **built-in activity part** (`layout.js`): root `div.chat-activity` (plus `is-live` while `input.live`). Three states:
           - live and closed: a header line `div.chat-activity-head`: `kit.statusDot(head, 'running')`, the current action `span.chat-activity-action` (mono), then `span.chat-activity-count` `· N steps` (`· 1 step` for one), then `span.chat-activity-time` `· <time>`; under it `div.chat-activity-shortlist` with one `div.chat-activity-step` per step of the latest `LIVE_STEP_LINES` steps, oldest first, the last one also `is-current`, a tool step whose result `isError` also `is-failed`; each line's text is the step's action text
           - live and open: the same header, no shortlist
           - not live (open or closed): one line `div.chat-activity-summary`: `N steps` (`1 step` for one), then `· <Tool> <count>` per tool name, then `span.chat-activity-failed` `· N failed` when any tool step failed, then `span.chat-activity-time` `· <time>` last (the time ends the line, after the failed count: design review)
           update rebuilds the root's children from the new input, so `update` never throws on a state change; a tick (only `now` changed) rebuilds the same way, which redraws only this line
           **time format** (the user's requirement), a function `spanText(ms)` in `layout.js`: whole seconds, rounded down, a negative span as `0s`; under a minute `<s>s` (`8s`, `42s`); under an hour `<m>m <ss>s` with two-digit seconds (`1m 05s`); otherwise `<h>h <mm>m` with two-digit minutes (`1h 02m`). The time is `(endedAt ?? now) - startedAt`. The formatting lives in the built-in layout, so a user layout formats its own time from the same three fields
           **summary rules**: tool names ordered by count, most first, ties by first use; a count of 1 prints the name alone; `thinking` and `raw` steps count toward `N steps` and are not named; failed counts tool steps whose `result.isError` is true. Action text: a tool's `toolLine(input)` (already in the file), `Thinking`, `Raw event`
           `const LIVE_STEP_LINES = 5;` at the top of `layout.js`, with a comment that a user layout changes the shortlist's length (the user's answer: in the layout, not a setting)
