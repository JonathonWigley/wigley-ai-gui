Decisions: **rows and stops**: the list keeps the last `entries`, a `working` flag (false at creation) and `openRuns: Set<string>`. After each `put`, `rebuild`, `setWorking` and toggle it computes `listRows(entries, working)`, then `order = cursorStops(rows, openRuns)`, then the focus as today (`focusAfterChange` over `order`). `following` and every scroll rule act on stops as they act on entries today
           **slots**: every entry keeps its own slot, built and redrawn as today. A step's slot also carries the class `chat-step-slot` and the `hidden` attribute (`element.hidden = true`) while its run is not in `openRuns`. Each run row has one slot `li.chat-entry-slot.chat-activity-slot`, keyed by its `runId`, inserted right before its first step's slot when the run first appears. A run slot's id is a stop id, so `is-cursor` and `scrollIntoView` reach it as they reach an entry slot
           **the part**: the run slot draws the layout's `activity` part through one `chatPartDraws(deps.layouts, 'activity', deps.log)` the list makes at creation, with a `surfaceBaseKit(deps.kit, 'chat', rollback)` kit, and the input `{ steps, current: steps.at(-1), live, open, startedAt, endedAt, now: deps.clock.now() }` (the `StepEntry` values pass as `StepInput`; `read-chat-layout.ts` already checks each variant fits its input). The run slot keeps the `DrawnPart` that `chatPartDraws.draw` returned and the input it last drew or updated with
           **when a run updates**: on each recompute, a run runs its part's `update` only when, against its last input, the steps differ (length, or any step object by identity: a replaced entry is a new object), or `live`, `open`, `startedAt` or `endedAt` differ. Every step is compared, not only the last, because parallel tool calls get their results out of order, and an earlier step's failed result changes the summary (design review; it widens the suggested last-step check at the cost of one shallow array compare). `now` is left out of this comparison: it changes only on a tick. An `update` that returns `'none'` or `'threw'` draws the part again into its slot. Every redraw (that one, and the redraw on `open` when the part has no update) first calls the old `DrawnPart`'s `dispose()`, then empties the slot, then draws. The list's `dispose()` calls `dispose()` on every run slot's `DrawnPart`
           **a failed draw**: a user `activity` part that throws, or whose `update` throws, draws with `default` through `chatPartDraws` (it logs `layout <name> activity update failed: <error>` for an update). A `default` draw that throws is logged as `default layout activity failed: <error>` and leaves `div.chat-entry.chat-raw` reading `activity` in the slot (plan.md § Decisions)
           **the live timer** (the user's requirement): while a live run is drawn, the list holds one pending `deps.timers.set(tick, 1000)`. `tick` runs the live run's part `update` with its last input and `now: deps.clock.now()`, with no comparison, and arms the next tick; `'none'` or `'threw'` redraws that part as above. No other slot redraws on a tick. When a recompute leaves no live run, the list clears the pending timer; when one appears, it arms one. `dispose()` clears it
           **open and close**: `toggleFocused` on a run stop flips its id in `openRuns`, shows or hides its step slots, updates its part with the new `open`, and on close applies `focusAfterClose(focus, runId, stepIds)` before recomputing the stops; it returns `'expanded'` or `'collapsed'`. On an entry stop it does what it does today. A `click` listener on the run slot runs the same flip without moving the focus
           **open state lifetime**: `rebuild` keeps `openRuns`; a run turning from live to finished keeps its open state; `dispose` clears it
           **`setWorking(working)`**: stores the flag and recomputes; a run updates only by the rule above
           **`ListStop`** for the focused stop: an entry slot's `{ kind: 'entry', entry }`, a run slot's `{ kind: 'activity', runId, steps }`
           **commands** (`chat-commands.ts`): `moveEntry` logs `focused activity line` for an activity stop and `focused <kind> entry` for an entry stop, `no entries in <name>` for null, as today. `toggleEntry` opens the image viewer only for an entry stop whose entry is a user entry with images; otherwise it calls `toggleFocused` and logs `<result> activity line` for an activity stop (`expanded activity line`, `collapsed activity line`), and for an entry stop what it logs today (`<result> <kind> entry`, `<kind> entry has nothing to expand`). `firstEntry`'s log lines do not change. `ChatSession.entries` in `chat-view.ts` picks the same member names
           **working flag**: `isWorking` is `state.running && state.activity === 'working'` (`waiting` is not working). `chat-view.ts` calls `tab.entries.setWorking(isWorking(tab.state))` after `tab.state` changes in the `activity`, `sessionRunning` and `sessionRested` handlers, and in `createTab` right after `entries.rebuild(state.entries)`. The `entry` and `entries` handlers need no call. 02 already edited `chat-view.ts` (the `is-box-focused` toggle); keep it
