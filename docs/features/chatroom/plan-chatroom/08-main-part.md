Arg errors reply an error result naming the field (`kind must be one of question, answer, blocker, heads-up, handoff, decision, result, progress, note.`), in the `parseShowArgs` style of `live-view/main/live-tools.ts`.
  - `chatroom_post` — `kind` (required, the nine `PostKind`s), `body` (required string), `to` (string array), `thread` (string; omitted → `session:<caller row id>`), `refs` (array of `{ type: 'file'|'branch'|'commit'|'plan'|'message', value: string }`), `replyTo` (integer), `answerBy` (ISO 8601 date-time string, stored as epoch ms; unparsable → arg error), `onNoAnswer` (string), `key` (string). The tool calls 05's `post` with `thread` null when omitted (05 defaults it to `session:<caller row id>`). Reply on success: `Posted #<id> in <thread>.` (the thread read back from the stored message), with `structuredContent: { id }`; `duplicate: true` replies `Already posted as #<id>.`; on `{ ok: false }` an error result holding 05's `reason`.
  - `chatroom_read` — `thread` (string) or `id` (integer), not both. Each form calls 05's `read(room, caller, query)` (`unread`, `thread` or `message`); 05 moves the cursor for `unread` only. Unread text: one line per `ReadItem`, `#<id> <from> · <kind> · <thread> · <text>`, plus ` · refs: <type>:<value>, …` when it has refs; none → `No unread chatroom messages.` `thread` and `id` text: each item `#<id> <from> · <kind> · <ISO time>` then its `text`, blank line between. 05's `ReadItem.text` is the first line for `unread` and the whole body for `thread` and `message` (05 owns this; check its Decisions). `{ ok: false }` → an error result holding 05's `reason`. `structuredContent: { items }` in every success.
  - `chatroom_board` — `boardFeed.rows(room)`; text `JSON.stringify({ room, rows }, null, 2)`, `structuredContent: { room, rows }`.
  - `chatroom_claim` — exactly one of `paths` (string array, non-empty), `branch` (string), `resource` (string); `reason` (required string); `minutes` (positive integer). `paths` items are made repo-relative first: an absolute path under `git.topLevel(session cwd)` becomes relative to it, a relative path is kept, and 05's `normalizeClaimPath` rule refuses the rest. Calls 05's `claim`; `{ ok: false }` → an error result holding its `reason`. Reply `Claim <id> holds <target> until <ISO time>.`, then one line per overlap `Overlaps claim <id> by <holder name>: <target> (<reason>).` `<target>` is the paths comma-separated, `branch <name>`, or `resource <name>`.
  - `chatroom_release` — `claimId` (string) or `all: true`, one of them. Calls 05's `release(room, caller, claimId or null)`. Reply `Released <n> claim(s).`; `{ ok: false }` → an error result holding its `reason`.

- **Hook handlers (`hook-handlers.ts`).** Registered in start as `sessions.addHookHandler(HOOK_PRE, pre)` and `(HOOK_POST, post)`. Each parses the request into `ChatroomHookRequest` (07's wire: `tool`, `paths`, `agentId`, `cwd`); a request that does not parse, or a session with no room → `{ text: null }` and a log line. The reply is always `{ text: string | null }` (07 prints only a non-empty text).
  - `pre`: the repo root is `git.topLevel(request.cwd)`; each path under it becomes repo-relative. Claim hits = `claimsTouching(room, { paths: <relative paths> }, caller)` (05 leaves out the caller's own row). For a `commit`, the request's paths are the staged paths 07 sends. Uncommitted hits = `boardFeed.uncommittedByOthers(session.id, <full paths>)`. No hit → `{ text: null }`. Each hit is one line (pinned): claim → `Chatroom: <path> is claimed by <holder name> (<reason>; <N> min left) — ask them in the room before you change it.`; uncommitted → `Chatroom: <path> has uncommitted changes from <name> — ask them in the room before you change or commit it.` `<path>` is relative to the request's `cwd` when under it, else absolute; `<N>` is the whole minutes to `expiresAt`, at least 1. At most 5 lines, then `… and <k> more.` Lines join with `\n`.
  - `post`: for `edit` and `write`, `boardFeed.noteTouched(session.id, agentId ?? MAIN_AGENT_ID, paths)`. Then `unreadAddressed(room, participant(session.id, agentId))`: N = 0 → `{ text: null }`; N = 1 → `1 chatroom message for you — chatroom_read`; N > 1 → `<N> chatroom messages for you — chatroom_read`.
- **Delivery (`delivery.ts`).** Hears `room.onMessage`. A message wakes a row's main agent by chat `send` when (a) its `to` holds that row's main agent and its kind is `question`, `blocker` or `handoff`, or (b) it is `userWord` and either its `to` holds that main agent, or its `to` is empty and the row's main agent posted in that thread before, or the thread is `session:<that row id>`. Only a row `chat.profileOf(rowId)` names (app-run) gets a send; terminal and Codex sessions read at turn boundaries. Idle is `chatSessionSlot` value `activity === 'idle'`: send at once. Busy: keep the wake pending, and on `chat.turnFinished` with `how: 'idle'` for that row send each pending wake whose message is still in `unreadAddressed(room, <main agent>)`. Each message wakes a row at most once; `sessions.ended` drops the row's pending wakes. A `send` that rejects is logged, as `shared/agent-forms/chat-wake.ts` does. Subagents are never `to` targets (05). Wake text (pinned): (a) `Chatroom: <sender name> sent you a <kind> in thread <thread>. Call chatroom_read to read it.`; (b) `Chatroom: the user wrote to you in thread <thread>. Call chatroom_read to read it.` Images `[]`.
- **Entries (`agent-entries.ts`).** Hears `chat.agentEvent`; skips `replayed: true`. `agentSpawned` → `roster.subagentSpawned`, then `addEntry({ room, thread: 'session:<row id>', from: <main agent participant>, kind: 'dispatch', body: 'dispatched <name> (<agentType>): <description>', refs: [] })`. `agentFinished` → `addEntry({ …, from: <subagent participant>, kind: 'hand-back', body: 'handed back (<outcome>)', refs: [] })`, then `roster.subagentFinished`. Every event, `fileWritten` included, also goes to `boardFeed`'s tracker (06's `fromAgentEvent`). A row with no room adds no entry.
- **joined and left.** On `sessions.connected` (every session, owned or connected): an entry `{ room, thread: 'session:<row id>', from: SYSTEM_PARTICIPANT, kind: 'joined', body: '<name> joined', refs: [] }`. On `sessions.ended`: the `left` entry the same way, with the room and name the roster read at connect (kept for this one use, since the session is gone at end), then `room.endClaimsOf(rowId)` and `roster.ended(rowId)`. Known gap: a session whose origin-repo lookup lands after connect posts `joined` under its folder name's room; later posts use the looked-up room.
