- **Hook handlers (`hook-handlers.ts`).** Registered in start as `sessions.addHookHandler(HOOK_PRE, pre)` and `(HOOK_POST, post)`. Each calls `arrive(session)`, then parses the request into `ChatroomHookRequest` (07's wire: `tool`, `paths`, `agentId`, `cwd`). 07's matchers are `Edit|Write|MultiEdit|NotebookEdit` (plus `Bash` for `pre`). 07 maps Edit, MultiEdit and NotebookEdit (path from `tool_input.notebook_path`) to `tool: 'edit'`, Write to `write`, and a Bash `git commit` to `commit`, so 08 handles `edit`, `write` and `commit` and names no Claude tool. A request that does not parse, or a session with no room → `{ text: null }` and a log line. The reply is always `{ text: string | null }` (07 prints only a non-empty text).
  - **Warning lines** (one function, used by `pre` and by the `post` fallback below). The repo root is `git.topLevel(request.cwd)`. A path not under the root is dropped; a null root drops every path. For each kept path, in request order:
    - Claim hits: `claimsTouching(room, { paths: [<target>] }, caller)` (05 leaves out the caller's own row). For `edit` and `write`, `<target>` is the repo-relative path. For `commit`, a path can be a folder (07 sends a folder pathspec as the folder), so `<target>` is `<repo-relative path>/**`: 05's `**` matches zero segments, so this still matches a file path. One line per (path, claim) pair: `Chatroom: <path> is claimed by <holder name> (<reason>; <N> min left) — ask them in the room before you change it.`
    - Uncommitted hits: `boardFeed.uncommittedByOthers(session.id, [<full path>], <under>)`, with `under` false for `edit` and `write` and true for `commit` (a changed file equal to the path or below it counts). One line per returned touch: `Chatroom: <touch path> has uncommitted changes from <name> — ask them in the room before you change or commit it.` `<name>` is the roster name of the touch's row and agent.
    - The path's claim lines come first, then its uncommitted lines.
    - `<path>` and `<touch path>` are relative to the request's `cwd` when under it, else absolute. `<holder name>` is the claim's `holder.name` as stored. `<N>` is `Math.ceil((expiresAt - now) / 60000)`, at least 1, with `now` from the clock.
    - At most 5 lines, then `… and <k> more.` Lines join with `\n`.

- **Delivery (`delivery.ts`).** Hears `room.onMessage`. A message wakes a row's main agent by chat `send` when (a) its `to` holds that row's main agent and its kind is `question`, `blocker` or `handoff`, or (b) it is `userWord` and either its `to` holds that main agent, or its `to` is empty and the row's main agent takes part in the thread (05's rule: it posted a non-entry, non-`progress` message there, a message there names it, or the thread is `session:<that row id>`). Rule (b)'s empty-`to` case is the case 05's `unreadAddressed` counts as the user's word to a thread, so the pending wake check, the hook's unread line and `chatroom_read` agree on it. Only a row `chat.profileOf(rowId)` names (app-run) gets a send; terminal and Codex sessions read at turn boundaries. Idle is `chatSessionSlot` value `activity === 'idle'`: send at once. Busy: keep the wake pending, and on `chat.turnFinished` with `how: 'idle'` for that row send each pending wake whose message is still in `unreadAddressed(room, <main agent>)`. Each message wakes a row at most once, whichever rule matched. `sessions.ended` drops the row's pending wakes. A `send` that rejects is logged, as `shared/agent-forms/chat-wake.ts` does. Subagents are never `to` targets (05). Wake text (pinned): (a) `Chatroom: <sender name> sent you a <kind> in thread <thread>. Call chatroom_read to read it.`; (b) `Chatroom: the user wrote to you in thread <thread>. Call chatroom_read to read it.` Images `[]`. The `Disposable` it returns stops listening and drops every pending wake.

- **Board feed (`board-feed.ts`).** It owns the board's inputs, so `board.ts` stays pure (06). It holds one `createTouchTracker`, a root per tracked row, and the last `GitFolderState` per root.
  - **Roots.** `track(rowId, folder)` resolves `git.topLevel(folder)` once, caches it as the row's root (null for a null folder or a null result), and then calls `refresh` for the row's room. A second `track` of a tracked row does nothing. `untrack(rowId)` drops the row's root.
  - **rows(room)** calls `buildBoard` with: `sessions` = every roster session of every room (`roster.sessions()`), each as a `BoardSession` with `room` = `roster.roomOf(rowId)` (a null room leaves the session out), `name`, `harness`, `folder`, `root` = the cached root, `hostSessionId` from the roster, `connected` true; `chat` from `chatSessionSlot`; `flows` from `workflow.flows()`, keyed by `sessionId`; `stageFinishes` = `workflow.stageFinishes`; `waitingOnUser` = the row ids whose `sessionsActivitySlot` entries hold one with emphasis `urgent` (`NEEDS_YOU_ACTIVITY`; that slot is page-owned and empty while no page is loaded, so the state then falls back to chat's activity); `pools` from the unity-pool snapshot slot; `git` = the map of last states keyed by `GitFolderState.root`; 05's `claims(room)` (held from the last refresh, since `rows` is sync); the tracker's `touches()`. `buildBoard` filters by room and looks up a session's git state by an exact match on `session.root`; the key and `session.root` both come from the same cached `git.topLevel` string.
  - **refresh(room)** re-reads git for each root of the room's sessions, one read at a time per root, at most one read every 2 seconds per root: a refresh inside the window runs once at the window's end. The returned promise resolves once each of those roots has had a read that started at or after the call, and never rejects. Each read reads the clock just before the call, as `readAt`, and calls `readGitFolder(git, root, readAt)`.
  - **After each read.** The feed stores the state under its `root`. Then it calls the tracker's `forget` with every touch under that root whose `at` is at or before `readAt` and whose path is not in `changed` (the full path of a changed entry is the root plus `/` plus the entry) — 06 § Stale touches. `onChanged(room)` fires when the room's rows differ from the last rows built for it.
  - **A rejected read** logs `board git read failed for <root>: <error>` and keeps the root's last state.
  - Start calls `refresh` on each `fileWritten` agent event, each hook `post`, each `chat.turnFinished`, each `sessions.connected` / `ended`, and each change of the chat session, workflow or unity-pool slots for a row in the room.
  - `noteTouched` calls the tracker's `touched` for each path with the clock's now, then `refresh` for the row's room.
  - `uncommittedByOthers(rowId, paths, under)`: for each full path, the root is the cached root that holds it. With `under` false, the path counts when it is in that root's last changed set. With `under` true, each changed file equal to the path or below it counts. For each counted file, the tracker's `latest(file)` is returned when its `rowId` is not `rowId`.
  - `settled()` resolves once every queued git read has settled. `stop()` clears the throttle timers, drops the queued reads, and resolves every pending `refresh` promise.
