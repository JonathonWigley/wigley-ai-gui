Decisions:
- **What moves.** `relay.py` keeps the MCP relay. `endpoint.py` takes the endpoint lookup and the channel open: `RELAY_PROTOCOL`, `HELLO_TIMEOUT_SECONDS`, `READ_SIZE`, `SocketChannel`, `PipeChannel`, `open_channel`, and a new `channel_path`. `start_app.py` keeps `Endpoint`, `endpoint_dir` and `read_endpoint`, since `start_app.py` and about 60 lines of its tests use them; `endpoint.channel_path` calls `start_app.read_endpoint`. Both modules stay standard library only.
- `relay.py` imports the module (`import endpoint`) and calls `endpoint.open_channel(...)`, `endpoint.channel_path(...)` and `endpoint.RELAY_PROTOCOL` through it, so a test that patches `endpoint.open_channel` or `endpoint.HELLO_TIMEOUT_SECONDS` reaches the relay. `Relay._connect` calls `endpoint.channel_path(self._endpoint_dir)` in place of `start_app.read_endpoint(...).channel`. `relay.py` still imports `start_app` for `start_app` and `endpoint_dir`.
- **Timeout parameter.** The two channel classes take `timeout` (seconds) in place of the module constant, read at construction; the default is `HELLO_TIMEOUT_SECONDS`, read at call time (write `timeout: float | None = None` and fall back to the module value, so a patch of `endpoint.HELLO_TIMEOUT_SECONDS` still takes effect, as test line ~1083 patches `relay.HELLO_TIMEOUT_SECONDS` today). 07 opens the channel with the time it has left of its 3 s deadline and calls `set_timeout` with the time left before each later `read` and `write`; both classes apply it as they apply the constructor value.
- **Codex id.** Today `session_id` is `CLAUDE_CODE_SESSION_ID` or None, and Codex sets no such variable, so every Codex hello says `null`. After: `hello_from_env(env, process_session_id)` sets `session_id` to `CLAUDE_CODE_SESSION_ID` when set; else, when `harness` is `codex` and `WIGLEY_SESSION_ROW` is unset, to `process_session_id`; else None. A Codex process the app started names its row by `row_id` and joins it by that (Lane H, `session-list.ts` `connect`); a `codex-…` id there would pin the join to an id the app's adapter never sets. `main()` calls `codex_session_id()` once and passes it, so every hello of one relay process (each reconnect included) carries the same id, and a new Codex process gets a new id. A Claude session with no `CLAUDE_CODE_SESSION_ID` keeps `null`, as today.

With the relay's id, a Codex session gets a hand-back while its relay process lives (an app restart under a live Codex session).
