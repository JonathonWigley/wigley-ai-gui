Decisions: `BoardRow` and its parts are JSON-safe: task 08 puts them in a slot and in the `chatroom_board` tool result. `harness` is the session's harness id as `SessionInfo.harness` holds it (`claude`, `codex`), null when the relay named none, never a label: a view that draws it labels it with `harnessLabel` (`src/shared/agent-harness-label.ts`).
           `buildBoard` is pure: no clock, no file, no git. Task 08 gathers the inputs and calls it (plan.md § Design Overview). `readGitFolder` is the one async read here, so task 08 runs git the same way for each root.
           **Rows.** One row per `inputs.sessions` item whose `room` equals `inputs.room`, in input order. Task 08 passes the live sessions of all rooms, and `buildBoard` filters by `room`: a touch by a session of another room then still finds its session's name. The sessions are app-run rows and connected terminal or Codex sessions (design.md § The board). Task 08 fills `hostSessionId` from the roster: the session's Claude Code session id, null when the row has none.
           **State**, first rule that holds:
           1. No `chat` key for the row (a terminal or Codex session): `connected` when `connected` is true, else `gone`.
           2. `waitingOnUser` holds the row, or `chat.activity` is `waiting`: `waiting`.
           3. `chat.activity` is `working`, or `chat.background` is above 0, or the row's flow `isBusy`: `working`.
           4. The row has a flow and `stageFinishes(flow)` is true: `done`.
           5. Else `idle`. A resting row (`running` false) is `idle`.
           `stageFinishes` and `waitingOnUser` are inputs because no main contract exposes them: forms has no main export or slot of open rounds, and `MainStage.finishes` is not on `SessionFlow` or `WorkflowMainExports`. Task 08 fills them.
           **Where.** `folder` is the session's folder. `branch` is the git state's `branch`, else `chat.branch`, else null. `clone` is the pool clone whose `path` is `samePath` with the session's `root`, in any pool of `pools`; null with no match or no snapshot. `holder` reads the clone's `claim`: null → `none`; `kind` `hold` → `user`; `row` equal to the row id → `this`; else a `session` equal to the session's `hostSessionId` (both not null) → `this`, which covers a terminal session whose claim has `row` null; else `other`. The board only reads unity-pool's state (design.md § The board).
           The git map's key is `GitFolderState.root`. `buildBoard` looks up a session's git state by an exact string match on `session.root`. Task 08 gets both strings from the same `git.topLevel` result.
           **Uncommitted.** For a session with a `root` and a git state for it: one `BoardFile` per path in `changed`, sorted in plain string order (`<`). The touch for a path is the touch whose `segmentsBelow(touch.path, root)`, joined with `/`, equals the path; the newest `at` wins; on equal `at`, the later item of `inputs.touches` wins. `byRowId` is that touch's row id. `by` is the `name` of the session with that row id in `inputs.sessions` (any room), or `an ended session` when none holds it. With no touch both are null: the file is unattributed (design.md § The board). With no root or no git state, `uncommitted` is `[]`.
           **Caps.** `uncommitted` lists at most 200 files, the first 200 in `<` order. `uncommittedMore` is the count of files left out, 0 when none. `unpushedPaths` lists at most 200 paths the same way, and `unpushedMore` counts the rest; it is 0 when `unpushedPaths` is null. Attribution runs for the listed files only.
           Two sessions in one folder both list the folder's changed files, each with its attribution.
           **Unpushed.** `unpushedPaths` is the git state's `unpushed`, sorted and capped (Caps); null with no upstream, no root or no git state. The Git contract has no commit count, so the board shows the unpushed paths and the branch in place of design.md's commit count.
           **Claims.** The claims of `inputs.claims` in the room whose `holder.rowId` is the row id and whose `expiresAt` is after `now`, a subagent's claims included, in input order.
           **readGitFolder** runs `currentBranch(root)`, `changedPaths(root, '.')` and `hasUpstream(root)`, then `unpushedPaths(root, '.')` only when there is an upstream; else `unpushed` is null. `readAt` is the value the caller passes: the caller reads the clock before it calls, so a write after that time is not lost. The result holds `readAt` and `root` as given. A rejection reaches the caller; task 08 logs it as `board git read failed for <root>: <error>` and keeps the root's last state.
           **Touch tracker.** It keeps the newest touch per file. Keys compare with `samePath`. A touch with an `at` equal to the kept touch's `at` replaces it (the later call wins); an older `at` does not. `touches()` returns the touches ordered by `at`, then by the call that stored them.
           **Stale touches.** A file that a session writes and commits between two git reads is never seen as changed, so its touch would stay and name the wrong writer later. The caller (task 08) removes such touches after each git read of a root: it calls `forget` with every touch under the root whose `at` is at or before the state's `readAt` and whose path is not in `changed` (the full path of a changed file is the root plus `/` plus the entry). A touch under a root with no git state stays for the app run; no row reads it. `touched` drops a path that is not absolute, and stores `normalize(path)`.
           `fromAgentEvent` reads only `fileWritten` events: `touched(event.sessionId, event.event.agentId, event.event.path, event.event.at)`. `fileWritten` is the harness-neutral record of a finished Write, Edit, MultiEdit or NotebookEdit (`src/contracts/agent.ts`, `WRITE_TOOL_PATHS` in `src/plugins/claude-code/main/stream-decoder.ts`); `toolStarted` carries no path. A replayed event counts too: after an app restart, the replay gives back the attribution.
           Task 08's hook handler calls `touched` with the hook's `paths` and `agentId` (or `MAIN_AGENT_ID`) for terminal Claude sessions (design.md § The hook).
           `forget` removes the touches of the given full paths. Task 08 calls it with the paths that left a root's changed set between two git reads, so a committed file loses its old attribution.
           The tracker lives in memory for the app run. It writes no file.
