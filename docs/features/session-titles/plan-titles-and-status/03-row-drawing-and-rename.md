Decisions:
- **Activities.** `top` is the highest `rank` of the session's activities, the last `set` winning a tie; `set(..., null)` removes that source's. `setActivity` redraws the side bar only when `set` returns true. `sessionRemoved` calls `forget`. A set for a session with no row yet is stored and shows once its row arrives (chat's tab can start before sessions' `sessionAdded`). Activities live in the page and start empty on a page load.
- **Row input.** `title` is `shownTitle(row.titles, titleLimit(settings.titleMaxLength))`. Page `start.ts` subscribes with `api.onSettingsChanged` and redraws the side bar when `titleMaxLength` changed, disposing the subscription with the part; `activity` is `top`'s word and tone. The app-kept tooltip becomes the non-null parts of `title`, `label`, `status` joined with ` · `.
- **Activity set before its row.** A `set` for a session with no row is stored and shows once its row arrives; one arriving after `sessionRemoved` is stored too, a small record never drawn (session ids are random and never reused) — accepted.
- **Default row** (`layout.js`): `kit.row` with `label: input.title ?? input.label` and `detail: input.title === null ? null : input.label`; when `activity` is set, a `kit.statusDot` plus `span.session-row-activity` holding the word, both in `kit.rowTrailing(element)`; the `marked` attention dot only when `activity` is null; the status second line and `contributedParts` as now. The dot pulses while its tone is `running`: `@keyframes session-dot-pulse` from `opacity: 1` to `opacity: 0.4` in `sessions.css`, applied as `animation: session-dot-pulse var(--wg-duration-slow) var(--wg-ease-out) infinite alternate` on `.session-row .ui-dot[data-status='running']` (reduced motion makes the duration instant, which stops the pulse — accepted). If `scripts/check-styles.mts` refuses `@keyframes` or the easing token is named differently, use the nearest token the tree has and say so in the commit.
- **Row line layout** (`sessions.css`): the title column (`.ui-row-label`) shrinks first (`minmax(0, max-content)`); the detail (folder label) is `minmax(0, max-content)` too, ellipsizing only once the title is at its least; the trailing cell is `max-content` and never shrinks, holding the dot then the word with `--wg-space-1` between. Rewrite the comment above the grid to say this.

- **Rename dialog** (`rename-dialog.ts`): built on `createDialog` (`src/shared/page/ui/dialog.ts`) with one text box, following the docs rename dialog's shape (`src/plugins/docs/page/docs-dialogs.ts`) for its pushed key scope, Enter and Esc. The dialog element joins the overlay area as sessions' picker does (`api.areas.overlay.contribute`); its scope is pushed with `api.keys.pushScope('rename')`, and the pushed scope's `onBaseChanged` cancels it, as docs' dialog does. Heading `Rename session`; the box prefilled with `editableTitle(row.titles)` (uncut, so a first-message title never stores a `…` the user did not type); hint line `Empty hands naming back to the agent.` The session id is captured when the dialog opens. Enter: a box that normalizes to empty invokes `setUserTitle(id, null)`; otherwise a `titleProblem` keeps the dialog open with the problem under the box, else it invokes `setUserTitle(id, text)`. It closes when the invoke resolves; a rejection keeps it open with the error text under the box. Esc closes and changes nothing. The `then` logs `[sessions] renamed <label> to "<title>"` or `[sessions] cleared the user title of <label>`.
- **`renameSession`** acts on the focused pane's session (`selectedSessionId()`), like `closeSession`: with Sessions mode hidden it logs `[sessions] rename ignored: Sessions mode is hidden`; with no session it logs `[sessions] no session to rename`; with the dialog already open it does nothing. Manifest: `renameSession: { label: 'rename the session', group: 'sessions', runsIn: 'page' }` (the group matches its neighbours' group in the manifest).
