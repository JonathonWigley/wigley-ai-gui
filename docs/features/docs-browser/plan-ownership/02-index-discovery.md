Decisions:
- **Marketplace clone**: a repo whose root holds `.claude-plugin/marketplace.json`. Each listed plugin whose `source` is a string starting `./` is walked with `_walk_plugin_components(scan, <source real folder>, owner, "claude")`, so skills, agents, commands, `hooks/hooks.json` and the root `CLAUDE.md`/`AGENTS.md` are all walked. The owner is `Owner("repo", repo=<clone repo>, root=<clone real root>, plugin="<plugin>@<marketplace name>")`. `<marketplace name>` is the file's `name`. (pinned by lead)
- `marketplace.json` is read with `scan.env.claude_settings(path)`: an absent file reads `{}`, a malformed one prints the existing stderr line. A file with no `name` string, or no `plugins` list, makes the repo no marketplace clone. A plugin item that is no object, has no `name` string, or has a `source` that is not a `./` string is skipped silently. A source whose real path is no folder, or does not sit inside the clone's real root, is skipped. (Decided: a `github` source has no folder in the clone; AGENTS.md § Why the layout looks like this says every entry uses `./plugins/<plugin>`.)
- **No file becomes two entries.** Today the repo walk already claims a plugin folder's root `CLAUDE.md` and `AGENTS.md` as `instructions` (`_repo_file_kind` matches `INSTRUCTION_NAMES` at any depth), owned by the plain repo owner. Nothing else in a plugin folder is claimed by the repo walk (`skills/`, `agents/`, `commands/`, `hooks/hooks.json` are not under `.claude` or `.agents`). So `_walk_marketplace_clones` registers each plugin source folder's real path in `scan.owner_roots` with the clone plugin owner before it walks it. `owner_of` then settles every file under that folder, whichever walk claimed it first, to the clone plugin owner, through the existing deepest-owner-root rule. A file a walk already claimed keeps its kind. (verified in `discover.py`: `claim`, `owner_of`, `root_owner`, `_repo_file_kind`)
- Registering the plugin folder means every indexed file under it is a clone plugin file, an instructions file deeper than the plugin root included. Today the wigley plugin has none. (Decided)
- `_Scan.repo_names` keys by `owner.root`, not by the owner-root path. Today it keys by the `owner_roots` path; a plugin folder key would then appear as a repo root. For every repo owner the two are the same. (Decided)
- **Finding clones**: `_walk_marketplace_clones` walks each config root in `scan.config.roots` order with `scan.walk(root, prunes_generated=lambda dirpath, holds_git: True, follows_link=lambda dirpath, name: False)`. It reads folder listings only. A folder that `holds_git` and whose real path `scan.is_ignored` drops itself and every folder below (`dirnames[:] = []`). A folder that `holds_git` and holds `.claude-plugin/marketplace.json` as a file is a clone; it is registered with `scan.repo_owner(<real root>)`. A real root found twice is one clone. Walk order is clone order. Both `discover` and `discover_folder` call it, after the feature homes and before `_add_ancestor_instructions`. (Decided: `discover_folder` walks only the outermost repo holding the folder, so without this search a `context` or `session` run outside the clone would find no source and mark the user's own plugin third-party. A pruned folder walk of `D:/ai-dev` measured 0.13 s, 980 folders, on 2026-10-24.)
- **Origin URL**: the code already runs git (`Environment.origin_name` runs `git -C <root> remote get-url origin`, 10 s timeout). So add `Environment.origin_url(repo_root)`: that same call, returning the stripped stdout, or `None` on `OSError`, timeout, a non-zero exit or empty output. `origin_name` calls `origin_url` and keeps its result rules. (pinned by lead: reuse the git call the code already runs)
- **`repo_slug(url)`**: strip the URL, drop a trailing `/`, replace every `:` with `/`, split on `/`, drop empty parts. Fewer than two parts gives `None`. Else take the last two parts, drop a `.git` suffix from the last, join them with `/` and lower-case the result. So `git@github-personal:JonathonWigley/wigley-ai-marketplace.git`, `ssh://git@github.com/jonathonwigley/wigley-ai-marketplace.git`, `https://github.com/JonathonWigley/wigley-ai-marketplace` and `JonathonWigley/wigley-ai-marketplace` all give `jonathonwigley/wigley-ai-marketplace`. (pinned by lead)
- **`claude_marketplace_urls(config_dir)`** reads `<config_dir>/plugins/known_marketplaces.json` with the existing JSON reader. For each `<name>` whose value is an object holding a `source` object: `source.repo` when `source.source == "github"` and `repo` is a string; else `source.url` when it is a string; else the name is left out (a `directory` source has no URL). A value of the wrong shape is read through `setting_of_type`, so it prints the existing stderr line. (plan.md File Structure)
- **`codex_marketplace_urls()`** reads `codex_config()["marketplaces"]`. For each `<name>` table, `source` when it is a string. Wrong shapes go through `setting_of_type`. (plan.md File Structure)
- **Source of an install folder**: take the first install of the folder (as `_walk_plugins` does). Split its key at the first `@` into `<plugin>` and `<marketplace>`. Its URL is `<marketplace>` in the URL map of its harness: for `claude`, the maps of every folder in `scan.env.claude_config_dirs`, the first folder's value winning; for `codex`, `codex_marketplace_urls()`. The source is the first clone, in clone order, whose `repo_slug(origin_url)` equals `repo_slug(url)`, both not `None`. That clone must list a plugin named `<plugin>`; if it does not, the install has no source. (pinned by lead: first match in walk order wins; Decided: the plugin name must be listed)
- **Merge counterpart**: an install entry is an entry with `source "plugin"`, `root` the install folder, and `kind != "plugin"`. Its key is `Path(entry.path).relative_to(<install folder>).as_posix() + entry.id[len(entry.path):]`, so a hook keeps its `#hook:<event>:<n>` fragment. A clone plugin entry's key is the same, relative to the plugin's real source folder. Keys compare as plain strings, case-sensitive: `_Scan` dedups real paths by string today. (pinned by lead; verified: no case-folding compare in `discover.py`)
- A matched install entry leaves the entries. The clone entry gains `Installed(Location(<install entry path>, <install folder's plugin Owner from scan.owner_roots>), <first install's harness>, <first install's version>)`. Installed copies append in install-folder order: every config folder's Claude installs, then Codex's, as `_walk_plugins` orders them. An unmatched install entry stays `source: plugin`, `ownership: "mine"`. The install's own `kind: plugin` entry stays, `ownership: "mine"`. The install entry's own `walked` locations are dropped with it. (pinned by lead; Decided for the walked locations)
- An entry whose real path is outside the install folder is no install entry, even when a walk reached it through the cache (a user skill linked into a cache stays the user's entry, as `test_a_user_skill_linked_into_a_disabled_plugins_cache_is_listed_as_a_user_skill` requires). (Decided)
- **Third-party**: every entry of an install folder with no source, its `kind: plugin` entry included, is `ownership: "third-party"`. So is every entry with a location that `scan.env.locate_in_claude_config_dirs` places under `skills/synced/` (relative parts start `("skills", "synced")`), skill and skill-file alike. (pinned by lead)
- **Skill files**: `add_doc` with kind `skill` calls `self.add_skill_files(path, owner)` whenever `path` resolves to a file, whether or not this walk claims it. So a skill reached twice records its files' second paths as walked locations too. `add_skill_files` walks `path.parent` as walked with `self.walk(folder, prunes_generated=lambda dirpath, holds_git: True)`, so generated folders are pruned by `GENERATED_FOLDERS` and a linked folder is followed one level, as today. Every file but `<folder>/SKILL.md` is a candidate. A candidate whose first 8192 bytes hold a NUL byte is skipped before it is claimed. Each other candidate is claimed with `owner`; a new claim adds `_entry(owner or GLOBAL, "skill-file", real, <path relative to folder, "/" separators>, {"skill": os.path.realpath(path)})`. This covers every place a skill is found: global, synced buckets, `~/.agents/skills`, repo `.claude/skills` and `.agents/skills`, plugin installs (Codex's too) and clone plugins. Install copies of skill files merge like any other file. (pinned by lead; Decided: hooking `add_doc` reaches every skill walk with one change)
- The merge and ownership run in `_settle_ownership(scan, entries)`, called on `scan.finished_entries()` in both `discover` and `discover_folder`. It needs what the walks found, so `_Scan` keeps `plugin_installs: dict[str, list[PluginInstall]]` (real install folder → its installs, set by `_walk_plugins`) and `marketplace_clones` (each clone's real root, origin slug, marketplace name, and plugin name → real source folder, set by `_walk_marketplace_clones`). `Discovery` does not change. (Decided)
- An install folder that is also a clone plugin's source folder (a plugin installed from the clone in place) keeps today's behaviour: the clone plugin is not registered or walked. (Decided: the install already claimed every file there.)
- Update the `discover.py` module docstring: it names marketplace clones, the merge and ownership. Update the `environment.py` docstring: it also reads marketplace URLs. (Decided)
- Load states of merged entries are not this task's code: `Entry.locations` carries the installed copies to the rules (01). This task's `test_docs_index.py` test proves the end-to-end state. (pinned by lead)

## Lead rulings (cold plan reader)

- An instruction file name (`AGENTS.md`, `CLAUDE.md`, `AGENTS.override.md`, `CLAUDE.local.md`) inside a skill folder stays `instructions`, whichever walk reaches it first; every other file there is `skill-file`. Test: a fixture `skills/x/AGENTS.md` comes out `instructions` from both the repo walk and the plugin walk.
